## Fiber 树结构

### Fiber 节点关系

```
                    App (Fiber)
                       │
        ┌──────────────┼──────────────┐
        ↓              ↓              ↓
    return          child          sibling
        │              │              │
        ↓              ↓              ↓
    指向父节点      第一个子节点    下一个兄弟节点
```

### 完整的 Fiber 树示例

```jsx
// React 组件树
<App>
  <Header />
  <Content>
    <Article />
    <Sidebar />
  </Content>
  <Footer />
</App>
```

```
对应的 Fiber 树结构：

                        App
                         │ child
                         ↓
                      Header ────sibling──→ Content ────sibling──→ Footer
                         ↑                      │                      ↑
                         │                      │ child                │
                      return                    ↓                   return
                                             Article ──sibling→ Sidebar
                                                ↑                    ↑
                                                │                    │
                                             return              return
```

### 双缓存 Fiber 树

```
┌─────────────────────────────┐        ┌─────────────────────────────┐
│      current Fiber 树        │        │   workInProgress Fiber 树    │
│     (屏幕上显示的内容)        │        │     (正在构建的新树)          │
├─────────────────────────────┤        ├─────────────────────────────┤
│           App                │◄──────►│           App                │
│          /   \               │alternate│          /   \               │
│     Header  Content          │◄──────►│     Header  Content          │
│              / \             │        │              / \             │
│         List  Aside          │◄──────►│         List  Aside          │
│          /                   │        │          /                   │
│      Item(旧)                │        │      Item(新)                │
└─────────────────────────────┘        └─────────────────────────────┘

工作流程：
1. 更新开始 → 基于 current 树创建 workInProgress 树
2. 在 workInProgress 树上进行更新操作
3. 更新完成 → workInProgress 变成新的 current
4. 原来的 current 变成新的 workInProgress（复用）
```

## 渲染流程

### 完整渲染流程图

```
┌─────────────────────────────────────────────────────────────┐
│                      用户触发更新                             │
│     (首次渲染 / setState / useState / forceUpdate)            │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    创建 Update 对象                           │
│                  加入 updateQueue                             │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                   Scheduler 调度                              │
│  • 根据优先级排序任务                                          │
│  • 时间切片：每 5ms 检查是否需要让出执行权                       │
└─────────────────────────────────────────────────────────────┘
                            ↓
╔═════════════════════════════════════════════════════════════╗
║                   Render 阶段 (可中断)                        ║
╠═════════════════════════════════════════════════════════════╣
║  1. beginWork (递阶段)                                       ║
║     ├─ 根据 Fiber.tag 处理不同类型组件                        ║
║     ├─ 调用 render 方法或函数组件                             ║
║     ├─ 生成子 Fiber 节点                                     ║
║     └─ 标记副作用 flags                                       ║
║                          ↓                                    ║
║  2. completeWork (归阶段)                                    ║
║     ├─ 创建或标记更新 DOM 节点                                ║
║     ├─ 处理 props（className, style 等）                     ║
║     ├─ 收集副作用链                                           ║
║     └─ 向上归并副作用                                         ║
╚═════════════════════════════════════════════════════════════╝
                            ↓
╔═════════════════════════════════════════════════════════════╗
║                   Commit 阶段 (不可中断)                      ║
╠═════════════════════════════════════════════════════════════╣
║  1. Before Mutation 阶段                                     ║
║     ├─ 执行 getSnapshotBeforeUpdate                          ║
║     └─ 异步调度 useEffect                                     ║
║                          ↓                                    ║
║  2. Mutation 阶段                                            ║
║     ├─ 执行 DOM 操作                                          ║
║     ├─ 插入、更新、删除节点                                    ║
║     └─ 调用 useLayoutEffect 清理函数                          ║
║                          ↓                                    ║
║  3. Layout 阶段                                              ║
║     ├─ 执行 componentDidMount / componentDidUpdate           ║
║     ├─ 执行 useLayoutEffect 回调                              ║
║     ├─ 更新 ref.current                                      ║
║     └─ 异步调度 useEffect 回调                                ║
╚═════════════════════════════════════════════════════════════╝
                            ↓
┌─────────────────────────────────────────────────────────────┐
│              切换 current 指针                                │
│    current = workInProgress                                  │
└─────────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    用户看到新 UI                              │
└─────────────────────────────────────────────────────────────┘
```

```
performSyncWorkOnRoot / performConcurrentWorkOnRoot
                    ↓
            prepareFreshStack
         (创建 workInProgress 树)
                    ↓
            workLoopSync / workLoopConcurrent
                    ↓
        ┌───────────────────────┐
        │  performUnitOfWork    │
        │  ┌─────────────────┐  │
        │  │  beginWork      │  │  ← 递阶段：从父到子
        │  │  ↓              │  │
        │  │  处理当前 Fiber  │  │
        │  │  ↓              │  │
        │  │  创建子 Fiber    │  │
        │  │  ↓              │  │
        │  │  返回子 Fiber    │  │
        │  └─────────────────┘  │
        │          ↓             │
        │  ┌─────────────────┐  │
        │  │  completeWork   │  │  ← 归阶段：从子到父
        │  │  ↓              │  │
        │  │  创建 DOM 实例   │  │
        │  │  ↓              │  │
        │  │  处理 props      │  │
        │  │  ↓              │  │
        │  │  收集副作用      │  │

                    ↓
```

## 更新流程

### setState / useState 更新流程

```
用户调用 setState / setXxx
        ↓
创建 Update 对象
{
  lane: 优先级,
  payload: 新状态,
  next: 下一个更新
}
        ↓
加入 updateQueue
Update1 → Update2 → Update3
        ↓
标记 Fiber 需要更新
fiber.lanes |= lane
        ↓
调度更新
scheduleUpdateOnFiber
        ↓
Scheduler 调度
        ↓
进入 Render 阶段
```

### 优先级系统

```
┌─────────────────────────────────────────────────────┐
│              React 优先级级别                         │
├─────────────────────────────────────────────────────┤
│  NoLane              0    没有更新                   │
│  SyncLane            1    同步更新 (最高)              │
│  InputContinuousLane 4    连续输入 (拖拽)             │
│  DefaultLane         16   默认优先级                  │
│  TransitionLane      64   过渡更新                    │
│  IdleLane            高位  空闲更新 (最低)             │
└─────────────────────────────────────────────────────┘

调度示例：

高优先级任务    ┌──────────┐
(用户输入)   ──→│ 立即执行  │
                └──────────┘
                     ↓
中优先级任务    ┌──────────┐
(数据请求)   ──→│  等待    │ ──→ 高优先级完成后执行
                └──────────┘
                     ↓
低优先级任务    ┌──────────┐
(分析统计)   ──→│  推迟    │ ──→ 空闲时执行
                └──────────┘
```

## Diff 算法

### 单节点 Diff

```
场景：<div key="a">old</div> → <div key="a">new</div>

┌─────────────────────────────────────────────────┐
│  判断 key 是否相同?                              │
└────────┬────────────────────────────────┬───────┘
         │                                │
      相同 ✓                           不同 ✗
         │                                │
         ↓                                ↓
┌────────────────────┐            ┌─────────────┐
│ 判断 type 是否相同? │            │  删除旧节点  │
└────┬──────────┬────┘            │  创建新节点  │
     │          │                 └─────────────┘
  相同 ✓      不同 ✗
     │          │
     ↓          ↓
┌─────────┐  ┌─────────┐
│ 复用节点 │  │ 删除旧的 │
│ 更新属性 │  │ 创建新的 │
└─────────┘  └─────────┘
```

### 多节点 Diff

#### 场景 1：节点更新

```
旧: [A1, B1, C1]
新: [A2, B2, C2]

第一轮遍历：
  A1 vs A2 → key 相同，type 相同 → 复用，更新 props ✓
  B1 vs B2 → key 相同，type 相同 → 复用，更新 props ✓
  C1 vs C2 → key 相同，type 相同 → 复用，更新 props ✓

结果：全部复用，更新属性
```

#### 场景 2：节点新增

```
旧: [A, B, C]
新: [A, B, C, D]

第一轮遍历：
  A vs A → 复用 ✓
  B vs B → 复用 ✓
  C vs C → 复用 ✓
  
第二轮遍历：
  旧节点遍历完了，新节点还有 D
  → 创建 D

结果：复用 A B C，创建 D
```

#### 场景 3：节点删除

```
旧: [A, B, C, D]
新: [A, B, C]

第一轮遍历：
  A vs A → 复用 ✓
  B vs B → 复用 ✓
  C vs C → 复用 ✓
  
第二轮遍历：
  新节点遍历完了，旧节点还有 D
  → 删除 D

结果：复用 A B C，删除 D
```

#### 场景 4：节点移动

```
旧: [A, B, C, D]
新: [D, A, B, C]

第一轮遍历：
  A vs D → key 不同，跳出循环
  
第二轮遍历：
  1. 将剩余旧节点建立 Map
     {
       A: FiberA,
       B: FiberB,
       C: FiberC,
       D: FiberD
     }
     
  2. 遍历剩余新节点 [D, A, B, C]
     - D → 在 Map 中找到，复用并标记移动
     - A → 在 Map 中找到，复用并标记移动
     - B → 在 Map 中找到，复用并标记移动
     - C → 在 Map 中找到，复用并标记移动
     
  3. 检查 Map 中是否有剩余节点 → 无
  
结果：全部复用，调整位置
```

### Diff 算法复杂度对比

```
传统 Diff 算法：
  比较两棵树的所有节点
  时间复杂度：O(n³)
  
  Tree1        Tree2
    A            A
   / \          / \
  B   C        D   E
  
  需要比较：
  A-A, A-D, A-E
  B-A, B-D, B-E
  C-A, C-D, C-E
  
React Diff 算法：
  只比较同层级节点
  时间复杂度：O(n)
  
  Tree1        Tree2
    A            A        ← 只比较这一层
   / \          / \
  B   C        D   E      ← 只比较这一层
  
  只需要比较：
  A-A
  B-D, B-E
  C-D, C-E
```

## 事件系统

### React 合成事件系统

```
┌─────────────────────────────────────────────────┐
│                  用户操作                        │
│              (点击、输入等)                       │
└────────────────────┬────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────┐
│              原生 DOM 事件                        │
│         (浏览器捕获原始事件)                       │
└────────────────────┬────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────┐
│            事件委托 (根节点)                      │
│     所有事件统一绑定到 root 上                     │
│                                                  │
│     <div id="root">         ← 事件绑定在这里      │
│       <button onClick={...}>                     │
│     </div>                                       │
└────────────────────┬────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────┐
│          创建合成事件对象 (SyntheticEvent)        │
│     • 跨浏览器兼容                                │
│     • 事件池（优化性能）                          │
│     • 自动事件代理                                │
└────────────────────┬────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────┐
│              模拟捕获和冒泡                       │
│                                                  │
│     捕获阶段：root → parent → target              │
│     冒泡阶段：target → parent → root              │
└────────────────────┬────────────────────────────┘
                     ↓
┌─────────────────────────────────────────────────┐
│           调用组件事件处理函数                     │
│         onClick / onChange / ...                 │
└─────────────────────────────────────────────────┘
```

### 事件优先级

```
┌──────────────────────────────────────────┐
│           事件类型与优先级                 │
├──────────────────────────────────────────┤
│  离散事件 (DiscreteEvent)                 │
│    click, keydown, focus, blur...        │
│    → DiscreteEventPriority (高)          │
├──────────────────────────────────────────┤
│  连续事件 (ContinuousEvent)               │
│    scroll, mousemove, drag...            │
│    → ContinuousEventPriority (中)        │
├──────────────────────────────────────────┤
│  默认事件                                 │
│    其他所有事件                           │
│    → DefaultEventPriority (低)           │
└──────────────────────────────────────────┘
```

## Hooks 原理

### Hooks 链表结构

```
函数组件：
function Counter() {
  const [count, setCount] = useState(0);        // Hook 1
  const [name, setName] = useState('张三');      // Hook 2
  useEffect(() => { ... }, [count]);            // Hook 3
  return ...;
}

对应的 Fiber 节点：
┌─────────────────────────────────────┐
│         Counter Fiber               │
├─────────────────────────────────────┤
│  memoizedState: ──────┐             │
│                       ↓             │
│               ┌───────────────┐     │
│               │  Hook 1       │     │
│               │  state: 0     │     │
│               │  next: ────┐  │     │
│               └───────────┼──┘     │
│                           ↓         │
│               ┌───────────────┐     │
│               │  Hook 2       │     │
│               │  state: "张三" │     │
│               │  next: ────┐  │     │
│               └───────────┼──┘     │
│                           ↓         │
│               ┌───────────────┐     │
│               │  Hook 3       │     │
│               │  effect: {...}│     │
│               │  next: null   │     │
│               └───────────────┘     │
└─────────────────────────────────────┘
```

### useState 工作流程

```
首次渲染 (mount):
┌────────────────────────┐
│  调用 useState(0)       │
└──────────┬─────────────┘
           ↓
┌────────────────────────┐
│  创建 Hook 对象         │
│  {                     │
│    memoizedState: 0,   │
│    queue: updateQueue, │
│    next: null          │
│  }                     │
└──────────┬─────────────┘
           ↓
┌────────────────────────┐
│  返回 [state, setState]│
│  [0, dispatch]         │
└────────────────────────┘

更新阶段 (update):
┌────────────────────────┐
│  调用 setState(1)       │
└──────────┬─────────────┘
           ↓
┌────────────────────────┐
│  创建 Update 对象       │
│  加入 updateQueue      │
└──────────┬─────────────┘
           ↓
┌────────────────────────┐
│  触发组件重新渲染       │
└──────────┬─────────────┘
           ↓
┌────────────────────────┐
│  再次调用 useState      │
│  读取 Hook 链表        │
└──────────┬─────────────┘
           ↓
┌────────────────────────┐
│  计算新 state           │
│  返回 [1, dispatch]    │
└────────────────────────┘
```

### useEffect 工作流程

```
function App() {
  useEffect(() => {
    console.log('effect');
    return () => console.log('cleanup');
  }, [dep]);
}

执行时机：

Render 阶段：
  ┌─────────────────────────┐
  │  调用 useEffect         │
  │  创建 Effect 对象        │
  │  {                      │
  │    create: () => {...}, │
  │    destroy: undefined,  │
  │    deps: [dep],         │
  │    tag: HookPassive     │
  │  }                      │
  └────────┬────────────────┘
           ↓
  ┌─────────────────────────┐
  │  将 Effect 加入 Fiber    │
  │  的 updateQueue         │
  └─────────────────────────┘

Commit 阶段 - Layout 子阶段：
  ┌─────────────────────────┐
  │  异步调度 Effect         │
  │  (在下一帧执行)          │
  └────────┬────────────────┘
           ↓
下一帧：
  ┌─────────────────────────┐
  │  执行 cleanup 函数       │
  │  (如果有上次的)          │
  └────────┬────────────────┘
           ↓
  ┌─────────────────────────┐
  │  执行 create 函数        │
  │  保存返回的 cleanup      │
  └─────────────────────────┘
```

### useCallback / useMemo 原理

```
const memoizedValue = useMemo(() => computeExpensiveValue(a, b), [a, b]);
const memoizedCallback = useCallback(() => { doSomething(a, b); }, [a, b]);

┌──────────────────────────────────────────────────────┐
│              首次渲染                                 │
├──────────────────────────────────────────────────────┤
│  1. 执行 callback 函数，得到值                         │
│  2. 创建 Hook 对象                                    │
│     {                                                │
│       memoizedState: [value, deps],  // 保存值和依赖  │
│       next: null                                     │
│     }                                                │
│  3. 返回 value                                       │
└──────────────────────────────────────────────────────┘
                        ↓
┌──────────────────────────────────────────────────────┐
│              更新阶段                                 │
├──────────────────────────────────────────────────────┤
│  1. 读取 Hook 对象                                    │
│  2. 比较新旧 deps                                     │
│     if (areHookInputsEqual(nextDeps, prevDeps)) {    │
│       // deps 未变化，返回缓存的值                     │
│       return prevState[0];                           │
│     } else {                                         │
│       // deps 变化了，重新计算                        │
│       const nextValue = callback();                  │
│       // 更新缓存                                     │
│       hook.memoizedState = [nextValue, nextDeps];    │
│       return nextValue;                              │
│     }                                                │
└──────────────────────────────────────────────────────┘
```

## 性能优化策略

### 虚拟列表 (Virtual List)

```
┌────────────────────────────────────────┐
│            可视区域 (Viewport)          │  ← 只渲染可见的项
│  ┌──────────────────────────────────┐  │
│  │ Item 8                           │  │
│  │ Item 9                           │  │
│  │ Item 10  ← 渲染这些可见项         │  │
│  │ Item 11                          │  │
│  │ Item 12                          │  │
│  └──────────────────────────────────┘  │
├────────────────────────────────────────┤
│  总数据：10000 条                       │
│  只渲染：5 条 (可见的)                  │
│  性能提升：2000 倍                      │
└────────────────────────────────────────┘
```

### React.memo 优化

```
普通组件：
  Parent 更新 → 所有 Child 都重新渲染
  
  Parent
   ├─ Child1  ✓ 重新渲染
   ├─ Child2  ✓ 重新渲染
   └─ Child3  ✓ 重新渲染

使用 React.memo：
  Parent 更新 → 只有 props 变化的 Child 重新渲染
  
  Parent
   ├─ Child1 (props 未变) ✗ 不渲染
   ├─ Child2 (props 变化) ✓ 重新渲染
   └─ Child3 (props 未变) ✗ 不渲染

代码：
const Child = React.memo(function Child({ value }) {
  return <div>{value}</div>;
});
```

## 总结

通过这些图解，我们可以看到：

1. **React 架构是分层的**：核心层、协调层、渲染层各司其职
2. **Fiber 是核心创新**：可中断、可恢复、支持优先级
3. **Diff 算法很高效**：O(n) 复杂度，只比较同层级
4. **事件系统很智能**：事件委托、合成事件、优先级
5. **Hooks 基于链表**：顺序调用，不能在条件语句中使用

希望这些图解能帮助你更好地理解 React 的工作原理！
